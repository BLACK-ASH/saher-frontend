<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend 401 → client death path | Server-declared session death drives a client-side redirect; a malicious/compromised API could weaponize it |
| cached data → next browser user | Query cache survives in memory across login sessions on shared machines |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-01 | Tampering/Elevation (open redirect) | handleSessionDeath next param | mitigate | `next` is built ONLY from window.location.pathname+search (never from response bodies or query params), then encodeURIComponent — no off-site target reachable |
| T-2-02 | Information Disclosure (cross-session cache bleed) | QueryClient cache at death/logout | mitigate | cancelQueries() then queryClient.clear() wipes query+mutation caches before navigation (D-07); hard nav drops the React tree |
| T-2-03 | DoS (UX) — forced logout loop | provider onError filter | mitigate | Strict sentinel equality (`=== "Unauthorized"`); ordinary errors never trigger death; once-guard prevents re-entry storms |
| T-2-SC | Tampering | npm installs | mitigate | None in this plan — no package installs (RESEARCH Package Legitimacy Audit: no new packages phase-wide) |
</threat_model>
