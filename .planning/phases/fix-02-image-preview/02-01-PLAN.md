<objective>
Fix the root cause of FILE-01: uploaded image/file previews cannot be reliably rendered because the upload endpoints serialize Media in a shape that diverges from the canonical `{ alt, id, src }` contract used by every read path, forcing duplicated URL-to-src mapping and, in the Leave module, corrupting the stored reference.

Purpose: The backend reads already serialize Media documents as `{ alt, id, src }` (enforced by `imageType` in `libs/utils/zod-object-id.ts` and `normalizeDoc`), and the frontend already types uploads' rendered images as `{ alt, id, src }` everywhere (`use-me.ts`, `use-profile.ts`, `session.api.ts`, `imageType` tests). The ONE divergence is the upload controller responses (`upload/image.controller.ts`, `upload/document.controller.ts`), which return `{ id, fileName, url, size, mimetype }` — a `url` field instead of `src`, and no `alt` — so no single code path renders an upload, and each consuming module reinvents the mapping (`{ id, alt, src: data.url }`) or, in Leave, mis-stores `file.url`. Root cause is a backend response-shape inconsistency, fixed at the source so frontend callers collapse onto one convention and drop their per-module mapping.

Output: Backend upload endpoints return the canonical `{ id, alt, src }`; frontend `ImageUpload` and every upload consumer read `src`/`id` directly; Leave proof stores the Media ObjectId; image render paths are guarded against missing `src`.

This is a stabilization fix per FIX_PHASE.md — smallest safe change, no architecture change, no schema change, no DB migration (Media documents already store `src`/`alt`; the ObjectId refs remain the backend reference). The upload response shape changes, so backend openapi/ paths are updated and `pnpm docs:lint` + `graphify update .` are run (required when endpoints change).
</objective>
