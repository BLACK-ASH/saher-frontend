<objective>
Fix the authentication & authorization gaps identified in FIX_PHASE.md AUTH-01 and AUTH-02.

Purpose: AUTH-01 left newly-created users in a deadlock — blocked from login AND from requesting a verification email. AUTH-02 let revoked/deactivated users keep access through their existing access token and by refreshing tokens indefinitely from cached Redis sessions.

Output: Onboarding email carries a verification link; protected routes and token refresh check user active status; admin delete revokes the user's Redis sessions.

Note: Implemented in this session (backend repo src/auth, src/admin, src/libs). This record documents the completed Phase 0 plan.
