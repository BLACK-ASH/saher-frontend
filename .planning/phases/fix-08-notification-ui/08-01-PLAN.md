## Backend API (already exists — no backend changes needed)

Routes under `/api/notification/` (all behind `protectedRoute`):
- `GET /api/notification/?page=1&limit=10` — paginated list, returns `{ data: NotificationResponse[], meta: { page, limit, count, total } }`
- `GET /api/notification/un-seen` — returns `{ data: Notification[], meta: { count } }` (unseen for current user)
- `PATCH /api/notification/:id` — mark as seen, returns updated notification
- `POST /api/notification/` — create (admin write only)
- `POST /api/notification/subscribe` — push subscription
- `POST /api/notification/enable` — enable push
- `POST /api/notification/disable` — disable push

Notification shape (from backend schema):
```
{ id, type ("info"|"success"|"warn"|"error"), title, description, isSeen, seenAt, createdAt, expiresAt,
  action?: { type ("download"|"navigate"|"external"|"none"), label, url, method } }
```

## Conventions

- Service functions: `get<Resource>` / `<verb><Resource>` async arrow consts in `services/*.api.ts`
- Hooks: `useCamelCase` in `hooks/use-*.ts`, return flat object bag
- Schema: Zod, co-located in service file, type via `z.infer`
- All fetches through `apiFetch` from `lib/api-wrapper.ts`
- Imports use `@/*` alias, never relative
- Backend endpoints return `ApiResponse<T>` envelope: `{ success, message, data, meta? }`
