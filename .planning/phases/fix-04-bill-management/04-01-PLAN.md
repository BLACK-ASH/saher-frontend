BILL-02 root cause: The backend bill schema at ../saher-backend/src/reimbursement/bill/schema.ts uses `z.coerce.number()` for both `amount` and `advance` with no `.positive()` or `.min()` constraint. The Mongoose model at ../saher-backend/src/database/bill.model.ts also has no `min` validator on either field. A direct API POST with `{ "amount": -100 }` passes both Zod validation and Mongoose persistence.

Fix 1 — ../saher-backend/src/reimbursement/bill/schema.ts:
On the `billSchema` object (line 7-25), change:
- `advance: z.coerce.number()` → `advance: z.coerce.number().positive("Advance must be greater than zero")`
- `amount: z.coerce.number()` → `amount: z.coerce.number().positive("Amount must be greater than zero")`

This automatically applies to `userBillCreateSchema`, `userBillUpdateSchema`, `adminBillCreatSchema`, and `adminBillUpdateSchema` because they all `.pick()` from `billSchema`.

Note: The pre-existing uncommitted status enum addition in get-bill.schema.ts is unrelated — do not modify that file.

Fix 2 — ../saher-backend/src/database/bill.model.ts:
Add Mongoose-level validation as defense-in-depth:
- Change `advance: { type: Number, default: 0 }` to `advance: { type: Number, default: 0, min: [1, "Advance must be greater than zero"] }`
- Change `amount: { type: Number, default: 0 }` to `amount: { type: Number, default: 0, min: [1, "Amount must be greater than zero"] }`

Existing valid bills with amount >= 0 are unaffected (min: 1 only rejects negative and zero — existing bills already have positive amounts).
