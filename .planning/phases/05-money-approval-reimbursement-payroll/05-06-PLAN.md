## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → API | Settlement completion, advance issuance (money-moving writes on behalf of OTHER users) |
| API response → React state | Settlement/audit payloads parsed by zod before render |
| Notification channel | Export download link arrives later via notifications (Phase 7 AUDT-04 hardening) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06-01 | Tampering | Double-submitted settlement completing lifecycle twice | mitigate | D-26 gating; backend transitions settlement status statefully — second settle fails server-side |
| T-05-06-02 | Tampering | Forged advance amounts against arbitrary users | mitigate | Server authorize('write','preReimbursement') guards admin endpoints; UI restricted to finance-guarded page; zod validates positives client-side too |
| T-05-06-03 | Repudiation | Settlements without recorded terms | mitigate | Mode+description captured and persisted server-side; audit log visible in-dialog (D-14) |
| T-05-06-04 | Information Disclosure | Audit log/salaries exposed to staff viewers | mitigate | viewerCanAudit flag derived from can(read,'preReimbursement') gates BOTH rendering and the queries themselves (enabled:false ⇒ zero network exposure) |
| T-05-06-05 | Spoofing | Malicious export "download link" impersonation | accept | Links arrive through the authenticated notification system; rendering hardening owned by Phase 7 AUDT-04 — out of scope here, noted for hand-off |
| T-05-06-06 | Injection | Untrusted strings (reason/description/from/to) rendered as HTML | mitigate | Plain JSX text interpolation only; React escapes; no dangerouslySetInnerHTML in feature files |
| T-05-SC | Tampering | Package supply chain | accept | Zero installs |

No high-severity threats without mitigation coverage.
