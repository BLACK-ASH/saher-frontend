<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → API | All money reads/writes cross here; server authorizes via authorize() guards |
| API response → React state | Untrusted payloads parsed by zod before reaching UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01-01 | Tampering | Double-submit / replay of handle & settle calls | mitigate | Mutations expose isPending for UI gating (consumed by D-26 buttons in later plans); no optimistic writes so a duplicate click can never fabricate state; server remains authoritative |
| T-05-01-02 | Repudiation | Money actions without trace | mitigate | Every handle call carries `reason`; audit log surfaced in UI (plan 05-06) so actors are visible |
| T-05-01-03 | Information Disclosure | Balance/audit data leaking to unauthorized roles | mitigate | Endpoints RBAC-guarded server-side; audit/balance consumers gate rendering with can() in UI plans |
| T-05-01-04 | Elevation of Privilege | Client-side can() bypass | accept | UI gating is UX only; backend authorize() is the enforcement point (verified in RESEARCH) |
| T-05-01-05 | Denial of Service | Bulk loop hammering API | mitigate | Strictly sequential execution with per-item try/catch continue — bounded rate, partial failures isolated |
| T-05-01-06 | Spoofing | Session death mid-mutation | mitigate | Existing apiFetch single-flight refresh + retry-once + session-death handler (Phase 2) |
| T-05-SC | Tampering | Package supply chain | accept | Zero package installs in this plan (RESEARCH §Package Legitimacy Audit: none required) |

High-severity threats (T-05-01-01) are blocked by the automated no-optimistic-write test before this plan merges.
