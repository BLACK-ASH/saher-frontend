<objective>
Fix the root cause of soft-deleted Program / Session / Workshop records appearing in BOTH the Active and Deleted lists, and harden the backend list-query `isDeleted` parsing for consistency.

Purpose: DELETE-01/02/03 require deletion to be a soft delete where the record is excluded from the active query and included in the deleted query. The backend soft-delete implementation (isDeleted flag + isDeleted-scoped list queries + restore) is verified correct. Root cause is purely in the frontend React Query hooks: they accept `isDeleted` from the tab component but never forward it, so (a) the backend is never asked to filter by deletion state and (b) Active and Deleted tabs collapse to ONE identical React Query key that reuses the same stale cached list — hence a deleted record shows in both lists. DELETE-04 additionally requires the schema→service→controller→API→React Query→frontend chain to be consistent; the program list controller parses `isDeleted` differently from its session/workshop siblings, which is hardened here.

Output: The three list hooks forward `isDeleted`; the program controller parses `isDeleted` identically to the session/workshop controllers.

This is a stabilization fix per FIX_PHASE.md — smallest safe change, no architecture change, no feature regression. This plan is frontend-only for the hooks plus one defensive backend consistency line; NO endpoint signatures change, so the backend openapi/ docs:lint task (required only when endpoints change) is NOT triggered.
</objective>
