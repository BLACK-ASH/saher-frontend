# Plan 04-01: Code Quality Foundation + Shared UserSearchPicker

## Goal

Establish zod response schemas for mail and leave services, fix all filename/import bugs, and build the shared `UserSearchPicker` component that mail compose and Phase 5 advance bills will use. This plan delivers no user-visible features but makes all subsequent mail and leave plans possible.

## Tasks

10. Remove old hand-written `MailUser`, `MailT`, `MailInput` type/interface declarations — replaced by z.infer types.
11. Update all imports across the codebase that reference the old type names (`MailT` → `InboxMailT` or `OutboxMailT` as appropriate, `MailInput` → `SendMailInput`).

<acceptance_criteria>
- File `components/user-search-picker.tsx` exists and exports `UserSearchPicker` named component
- Props type: `{ value: MailUser[]; onChange: (users: MailUser[]) => void; label?: string; placeholder?: string; multiple?: boolean; disabled?: boolean }`
- Default `multiple` is `true`
- Component renders: chips above input (when value has items), text input below chips, dropdown below input when search results exist
- Chip styling: `rounded-full bg-muted px-2 py-1 text-sm` with user name + email + X remove button
- Debounce: 300ms using `useRef<NodeJS.Timeout>` + `setTimeout`/`clearTimeout` (no new dependency)
- Search fires only when input length >= 2 and after 300ms debounce
- Already-selected users (matching by `id`) are filtered out of search results dropdown
- Empty input hides dropdown
- Click on search result adds user to value array and clears input
- Click on chip X removes user from value array
- `pnpm lint` passes with 0 errors
</acceptance_criteria>

<action>
1. Create `components/user-search-picker.tsx` with "use client" directive.
2. Import `MailUser` from `@/services/mail.api`, `getSearchUser` from `@/services/mail.api`, `useQuery` from `@tanstack/react-query`, `useState`/`useRef`/`useCallback` from `react`, `X` from `lucide-react`, `cn` from `@/lib/utils`.
3. Define `UserSearchPickerProps` type with `value`, `onChange`, `label?`, `placeholder?`, `multiple?` (default true), `disabled?`.
4. Manage local `keyword` state. On input change, set keyword immediately (for display), but debounce the actual query firing by 300ms using a `useRef<NodeJS.Timeout>`.
5. Wire `useQuery` with key `["users", debouncedKeyword]`, queryFn calling `getSearchUser(debouncedKeyword)`, enabled when `debouncedKeyword.length >= 2`.
6. Render chip area: `value.map(user => <chip key={user.id}>name (email) <X onClick remove /></chip>)`.
7. Render input field with placeholder. On input change, update `keyword` state. On blur (with 150ms delay), clear dropdown.
8. Render dropdown: map `data` (filtering out users whose id is in `value`), each row shows name + email, onClick adds user to value and clears keyword.
9. Handle `multiple=false`: when a user is selected, show their name in the input as disabled text; clear on next input focus.
10. Handle keyboard: Escape closes dropdown. ArrowUp/Down navigate. Enter selects highlighted.
</action>
