# Plan 04-02: Complete Mail Experience

## Goal

The full mail experience works end-to-end: staff read paginated inbox with sanitized message view, compose with validated form and user-search picker, see sent items in outbox with multi-recipient display, and reply to any message. All inline picker duplication removed, form validated, body sanitized, pagination wired.

## Tasks

### Task 1: Wire pagination + fix invalidation in hooks/use-mail.ts

<read_first>
- hooks/use-mail.ts (current hook: single keyword param, no page/limit, send.onSuccess only invalidates "sent")
- services/mail.api.ts (after Plan 04-01: getMails/getSentMails now accept page/limit, normalizeList applied)
- hooks/use-attendance.ts (pattern: queryKey includes page/limit params, mutation invalidates broad key)
</read_first>

<acceptance_criteria>
- `useMail` accepts `{ keyword?: string; page?: number; limit?: number }` props (destructured from single object param)
- `inbox` query key is `["inbox", page, limit]` and queryFn calls `getMails({ page, limit })`
- `sent` query key is `["sent", page, limit]` and queryFn calls `getSentMails({ page, limit })`
- `send` mutation `onSuccess` invalidates both `["sent"]` AND `["inbox"]` query keys
- `user` query uses `keyword` from props, fires when keyword length >= 2
- `inbox.data` and `sent.data` expose `.items`, `.page`, `.totalPages` via normalizeList shape
- `pnpm lint` passes with 0 errors
</acceptance_criteria>

<action>
1. Change `useMail` parameter from `keyword?: string` to `{ keyword, page, limit }: { keyword?: string; page?: number; limit?: number } = {}` with defaults `page = 1`, `limit = 10`.
2. Update `inbox` useQuery: `queryKey: ["inbox", page, limit]`, `queryFn: () => getMails({ page, limit })`.
3. Update `sent` useQuery: `queryKey: ["sent", page, limit]`, `queryFn: () => getSentMails({ page, limit })`.
4. In `send` mutation `onSuccess`, add: `queryClient.invalidateQueries({ queryKey: ["inbox"] })`.
5. Return `{ inbox, sent, send, user }` — no change to return shape.
</action>
