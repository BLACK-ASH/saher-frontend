# Phase 9 — UI Design Contract

> Visual and interaction contract for Attendance Overhaul — Admin Oversight & UX Polish.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase delivers TWO distinct UI surfaces plus a nav + export refactor:

1. **Self-service `/attendance`** — chart repair (D-10), history date-range filter (D-11), clearer status card (D-12), export format selector (D-06).
2. **Admin/manager `/attendance`** (new, under `(admin)/`) — Range / Today / Monthly views, employee filter, paginated all-employee table, drill-down to employee history (D-01..D-05), admin export (D-07).
3. **Nav** — "All Attendance" entry for admin+manager (D-05).

## Surface A — Self-service `/attendance` (existing page)

Page composition stays `app/(main)/attendance/page.tsx:6-19` — 3-col grid (`AttendanceStatus`, `AttendanceChart` md:col-span-2; row 2 `AttendanceTable` col-span-2 + `AttendanceCorrectionRequests`).

### A1. Status card (`attendance-status.tsx`) — D-12 clarity pass (LIGHT)

Changes only — keep layout, add clarity:

```
Card > CardHeader (CardTitle = formatIstDate(data.date), CardAction = status Label)
  > CardContent (3 rows: Check In / Check Out / Work Hours — keep disabled Inputs)
  > CardFooter (2x2 grid: Check In / Check Out / Week Off / Overtime buttons)
```

- **Status label**: replace `<span className="rounded-md bg-muted px-3 py-1 text-sm font-medium">` with `<Badge variant>` using the derived `AttendanceStatus` enum (`hooks/use-attendance.ts:11-16`). Map:
  - `NOT_CHECKED_IN` → `outline` + "Not Checked In"
  - `CHECKED_IN` → `success` + "Checked In"
  - `LATE` → `outline-warn` + "Late"
  - `CHECKED_OUT` → `default` + "Checked Out"
- **Readout clarity**: give each disabled Input a `sr-only`-safe aria-label + keep value. Add a subtle `tabular-nums` class on the Work Hours Input for numeric alignment (optional, minor).

### A2. Chart (`attendance-chart.tsx`) — D-10 fix (server month range)

Root cause = `useAttendance` default `limit=7` (`hooks/use-attendance.ts:26,38`) feeds the 7 newest records. Fix at the DATA layer, not the chart:

```
Card > CardHeader (CardTitle "This Month Work Hour", CardDescription getMonthYear(firstDay))
  > CardContent > ChartContainer > BarChart (recharts, existing)
```

- **Data source change**: chart must NOT consume the shared `attendancesList` (7-row hook). Add a dedicated month query — prefer `getAttendance({ sort:'asc', page:1, limit:31 })` capped at 31 OR add a `startDate/endDate` month-scoped service fn against `/user/me` **only if backend supports range** (RESEARCH Pitfall 5: `/user/me` has NO date-range support). **Safe contract:** use a new `useMonthAttendance` hook calling `getAttendance` with `limit=31` (asc). Do **not** bump the shared `useAttendance` default.
- **Chart data**: keep `chartData = data.items.map(a => ({ date, workHours }))`, XAxis tickFormatter `formatIstDate`, `Bar dataKey="workHours"` fill `var(--color-desktop)` (chart-1), radius 4. Keep `accessibilityLayer`, `CartesianGrid vertical={false}`, `ChartTooltip`.
- **Empty/loading**: keep `DefaultLoader` (col-span-2) and `NoData` states.

### A3. History table (`attendance-table.tsx`) — D-11 date-range filter

Add a filter bar + keep pagination:

```
Card > CardHeader (CardTitle "Recent Attendances", CardAction = [export dropdown, refresh, PaginationFooter])
  > NEW filter row (between footer and CardContent)
  > CardContent > Table (Date / Check In / Check Out / Work Hours / Status / Late / Action)
```

**Filter row behavior (two native date inputs — established pattern, RESEARCH Pattern 4):**
```
<div className="flex flex-wrap items-end gap-3 border-b px-4 py-3">
  [Field: Start Date <Input type=date> max=endDate>]  [Field: End Date <Input type=date> min=startDate>]
  [Button variant=outline "Apply"]  [Button variant=ghost "Reset"]
</div>
```
- Local state `startDate`/`endDate` (`string`, `YYYY-MM-DD` IST via `dateToIstDateOnly`).
- Cross-constraint: `startDate` max = `endDate`; `endDate` min = `startDate` (matches `attendance-toolbar.tsx:58-71`).
- **Apply** commits to the query; **Reset** clears both and re-queries default (page 1).
- **Endpoint constraint (RESEARCH Pitfall 5)**: `/user/me` (used by `getAttendance`) has NO date-range filter. Contract: implement client-side filtering of the fetched page against `startDate`/`endDate` (string compare on `attendance.date`) — pragmatic and in-scope — OR if a backend month/range param is confirmed for `/user/me`, use it. **Default to client-side filter** on the already-fetched page; document in a comment. Reset page to 1 on Apply (D-23 pattern: render-phase state adjust).
- Table columns/status/action unchanged; reuse `attendanceStatusVariant` + existing `AttendanceCorrectionSide` sheet trigger.

### A4. Export (`attendance-report.tsx`) — D-06 format selector

```
DropdownMenu (trigger Button size default variant outline, Download icon + "Export Report")
  > DropdownMenuContent align=end
      Today / Week / Month / Year / Last N Days / Custom Range   (existing items)
      ─ (Separator)
      "Format: PDF" / "Format: Excel (XLSX)"   (NEW — sets format, then triggers selected type)
```
- **Behavior**: keep the existing 6 range items. Add `format` state `"pdf" | "xlsx"` (default `"pdf"`). Each range item appends `format=${format}` to the `generateReport` query (backend validated `pdf|xlsx`, RESEARCH code example). The "Last N Days" / "Custom Range" dialogs keep working, now passing `format`.
- **Format sub-menu**: use a nested `DropdownMenuSub` OR a second `DropdownMenuItem` row. **Simplest:** two `DropdownMenuItem`s `"PDF"` / `"Excel (XLSX)"` that set format state and show a `CheckIcon` on active; label the current selection in the trigger caption. No `DropdownMenuSub` needed unless the nested pattern is trivial — decide at implementation, keep it one level.
- **Loading state**: `generateReport` already toasts success/failure via `apiFetch`; add a local `isGenerating` state disabling the trigger + showing `Loader2 animate-spin` while the request is in flight (prevents double-submit, D-26 money-safety pattern applies to report triggers too).
- Preserve the existing `Dialog`es for "Last N Days" and "Custom Range".

### B2. Feature composition (`features/attendance/admin/`)


**State owned by the page (or a `use-admin-attendance` hook):**

- `startDate` / `endDate` (`YYYY-MM-DD` IST strings, default = current month start/end via `dateToIstDateOnly`)

### B3. View switcher (segmented)

Reuse `Tabs` if a shadcn Tabs exists, else a row of `Button variant={view===x ? "secondary" : "ghost"}` (matches the "Human verify"-style pills seen in the codebase). **Contract: three equal buttons** with `CheckIcon`-free text:

```
[ Range ] [ Today ] [ Monthly ]
```
- **Range** → `GET /retrieve` with `startDate&endDate&sort&page&limit` + employee filter (if employeeId). 
- **Today** → `GET /today` (`getTodayAttendance`) — all employees today, paginated. Note: single-day, Redis-cached, admin/manager-only (RESEARCH Pitfall 2 warning: do NOT substitute `/today` for range).
- **Monthly** → `GET /retrieve` with `startDate`=month-start, `endDate`=month-end (computed via IST helpers) — all employees, whole month.

### B4. Filter toolbar (Range view; optional for Monthly)

Follows `attendance-toolbar.tsx` pattern (two native date inputs) + employee filter:

```
<div className="flex flex-wrap items-end gap-3 border-b px-4 py-3">
  [Field Start Date] [Field End Date]
  [Employee filter — Select or searchable input]   ← Optional
  [Button "Apply"] [Button ghost "Reset"]
</div>
```
- **Employee filter**: prefer a `Select` populated from the user directory. No list-all endpoint exists (D-32), so use the user-search pattern from Phase 4/6 (`useUserMap` / search query) — a searchable `Input` + `Select` of matches, or `Select` fed by cached `["users",*]` map. **Default:** reuse the existing user-search picker pattern (Phase 4 `UserSearchPicker`) if available; else a `<Select>` backed by `useUserMap`. Keep it lightweight — an `employeeId` string filter appended to `/retrieve` only if backend supports a user param; otherwise filter the fetched page client-side by `attendance.user.id`.
