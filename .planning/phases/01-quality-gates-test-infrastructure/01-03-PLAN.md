<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → host deploy dir | Self-hosted runner resets a working copy and builds containers; workflow edits alter what executes on that host |
| CI logs | Step output is visible to anyone with repo read access |
| pnpm install on runner | Dependency resolution at deploy time could drift from local testing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SC | Tampering | pnpm install during deploy | mitigate | `--frozen-lockfile` pins the exact lockfile tested locally; no range re-resolution on the runner |
| T-01-SEC | Information Disclosure | workflow step output/logs | accept | Gate steps print tool versions and test results only — no secrets exist in this repo's workflows, none introduced |
| T-01-WF | Tampering | workflow file itself | accept | Solo-developer project; direct-to-dev commits are the established flow; the Task-3 checkpoint puts a human review between edit and activation |
| T-01-AV | Denial of Service | deployment availability | accept | Gates failing = deploy aborted is the intended behavior (D-03); a red gate blocks Test env updates until fixed, which is the point |

</threat_model>
