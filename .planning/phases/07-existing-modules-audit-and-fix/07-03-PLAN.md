# 07-03-PLAN: Profile Auth Flows

## Goal
Implement clear pending/success/expired states for email/password token-confirm flows (AUTH-02) and add active sessions view with revoke action in profile (AUTH-03).

## Tasks

### Task 1: Add active sessions query + revoke mutation to useProfile
**read_first:**
- hooks/use-profile.ts
- lib/api-wrapper.ts
- hooks/use-sessions.ts (pattern for mutations)

**acceptance_criteria:**
- `hooks/use-profile.ts` exports `useProfile` returning `{ profile, sessions, revokeSession }`
- New query: `queryKey: ["user", "sessions"]`, `queryFn: GET /api/auth/sessions` (returns `SessionT[]`)
- New mutation: `revokeSession` → `DELETE /api/auth/sessions/:id`, invalidates `["user", "sessions"]`, toasts success
- Types: `SessionT` with `id, device, ip, lastActive, current` fields
- If backend lacks `/api/auth/sessions`, add stub that returns `[]` and document — backend must implement

### Task 2: Add Active Sessions UI to profile page
**read_first:**
- features/profile/profile.tsx
- features/profile/email-verification.tsx (pattern for accordion section)
- components/ui/accordion.tsx

**acceptance_criteria:**
- Profile page adds `<Accordion>` section "Active Sessions" in right sidebar
- Lists sessions from `sessions.data` with: device, IP, last active (IST format), "Current" badge for current session
- Each session has revoke button (disabled for current session)
- Revoke opens confirm dialog → calls `revokeSession.mutate(id)` → toast success → list refreshes
- Uses `formatIstDateTime` from `lib/date` for timestamps

### Task 3: Add pending/success/expired states to change-email flow
**read_first:**
- features/change-email/components/change-email-form.tsx
- hooks/use-login.ts (mutation pattern)

**acceptance_criteria:**

- On error: toast error with specific message (check for "token expired" / "invalid token" in `res.message`)
