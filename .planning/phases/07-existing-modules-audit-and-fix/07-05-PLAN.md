# 07-05-PLAN: Shared Trash Pattern Enforcement (Realized to Audit)

## Goal
Ensure one shared trash UX pattern (TrashTabPattern + Active/Deleted tabs) covers every soft-deletable resource, and document which resources are NOT soft-deletable so the trash pattern is not forced onto them.

## Tasks

### Task 1: Audit all soft-deletable resources ✅ (complete)
**acceptance_criteria:**
- Documented list of all resources with soft-delete: programs, workshops, sessions, participants, reimbursement bills, notices, bank accounts
- Each has `isDeleted` filter on list endpoint and `restore` endpoint
- Documented list of resources WITHOUT soft-delete: users (uses `isActive` not `isDeleted`), attendance corrections (status workflow), leave, mail, payroll (immutable)

### Task 2 (REALIZED): Users use isActive, not isDeleted — no tabs needed
**acceptance_criteria:**
- `getAdminUsers` returns all users; trash distinction is the `isActive` field, already surfaced in `user-action.tsx` (Delete vs Restore / Delete Permanently dropdown)
- No Active/Deleted tabs are added — the frontend has no `isDeleted` filter for `/api/admin/users`, and forcing tabs would contradict the audit.
- Documented decision logged in SUMMARY.

### Task 3 (REALIZED): Attendance corrections — status workflow, not soft-delete
**acceptance_criteria:**
- Confirmed backend uses status workflow (pending/approve/reject), no `isDeleted` filter.
- AUDT-05 satisfied by status pattern, not a trash tab.
- Documented.

### Task 4 (REALIZED): Leave — not soft-deletable
**acceptance_criteria:**
- `getLeaveApplications` / `getAllLeaveApplications` have no `isDeleted` filter and no restore endpoint.
- Documented.

### Task 5 (REALIZED): Mail — not soft-deletable
**acceptance_criteria:**
- `getMails` / `getSentMails` have no `isDeleted` filter and no restore.
- Documented.

### Task 6 (REALIZED): Payroll — immutable, not soft-deletable
**acceptance_criteria:**
- `getPayrollList` has no `isDeleted` filter; payroll records are immutable.
- Documented.

### Task 7: Conformance check on soft-deletable modules
**read_first:**
- features/program/program/all-programs.tsx
- features/program/workshop/all-workshops.tsx
- features/program/session/all-sessions.tsx
- features/program/participant/all-participant.tsx
- features/noticeboard/notice-trash.tsx
- features/reimbursement/recycle-bin.tsx

**acceptance_criteria:**
- Confirmed all genuinely soft-deletable modules already use Active/Deleted tabs or TrashTabPattern
- No code changes required; the pattern is already consistently enforced

### Task 8: Run lint/typecheck
**acceptance_criteria:**

## Verification
- Soft-deletable modules (program, notice, reimbursement) show Active/Deleted trash pattern
- Non-soft-deletable modules (users, attendance, leave, mail, payroll) are documented as not requiring the pattern
- No forced/invented trash UI on modules where the backend provides no delete

## Must-haves for goal-backward verification
