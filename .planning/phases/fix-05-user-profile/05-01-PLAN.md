# Root-cause findings (from this planning session)

## USER-01 (bank name as a number)
Traced Input -> react-hook-form -> zod -> request payload -> controller -> service -> Mongoose:
- Frontend `features/register/register-schema.ts` `bankDetailSchema.bankName = z.string()`; `bank-details.tsx` Controller `name="bank.bankName"`; `user-register.tsx` submits the bank triplet.
- Backend `src/admin/account/schema.ts` `bankSchema.bankName = z.string()`; `account/controller.ts` `new Bank(registerInput.bank)`; `src/database/bank.model.ts` `bankName: { type: String }`.
- **All current mappings are correct — there is NO `bankName: accountNumber` swap in the current source.** The symptom is caused by malformed data persisted from an earlier write while an earlier mapping defect was live, plus one live gap:
  - `features/register/user-register.tsx` bank `defaultValues` (lines ~51-57) OMIT `accountNumber`, even though the schema requires it and the step-2 trigger list (line 78) validates `bank.accountNumber`. The field has no defined default.
- Fix scope: (1) add the missing `accountNumber` default; (2) lock the string contract with regression tests at both the frontend schema and backend account-register/self-read levels so a future mapping swap cannot silently occur. Do NOT fabricate a DB migration — there is no confirmed live defect in the current code path to migrate.

## USER-02 (cannot view profile)
Trace `/profile` -> `useProfile` -> `GET /api/user` -> `userGetController` -> `getAccountByUser(req.user.id)`:
- When the logged-in user has NO fully-onboarded `Account` doc (e.g. seeded users, users created outside the atomic onboarding flow), `getAccountByUser` returns `null` -> the controller throws 404 'User Not Found' -> `profile.tsx` line 41 renders `<NoData title="No Profile To Show">` (a blank experience, not an error).
- When an `Account` doc exists but a populated KYC Media ref is missing/deleted, `accountSchemaFinal.parse` in `getAccountByUser` THROWS -> 500 -> `apiFetch` toasts and rejects -> profile page fails. This is because `aadhar`/`pan`/`resume` are typed as non-null `imageType` and a raw unpopulated ObjectId fails that parse.
- The response is cached under `createKey('account','userId',id)`; once a bad/stale shape enters the cache it persists for TTL.
- Self-read relies on `/api/user`; a user must be able to view their identity regardless of KYC completeness. Dependency: Phase 0 (`fix-00-auth`) already fixed `/api/auth/me` and the `protectedRoute` guard; this profile path reuses that same guard (already working in the sidebar via `useMe`).
- Authorization is enforced at the guard (`protectedRoute`) and the controller only ever reads `req.user.id` for self-read — no cross-user exposure. Keep it that way.

# Security / contract note
`accountSchemaFinal`'s KYC fields become nullable in the response -> this is an OpenAPI response-shape change. Per backend conventions you MUST update `openapi/openapi.yaml` and run `pnpm docs:lint` + `graphify update .` in the backend after the response contract changes.
