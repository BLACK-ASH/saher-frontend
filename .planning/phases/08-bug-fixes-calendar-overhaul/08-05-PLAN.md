    Three backend fixes in one task:

    **1. Fix month boundary (D-12, RESEARCH F1/Pitfall 1):**

    In `../saher-backend/src/libs/utils/calendar.ts`, replace the server-local `new Date(year, month, 1)` boundaries with IST-explicit computation. The frontend sends dates as `+05:30` ISO strings (via `dateInputToIso` from `lib/date.ts`). The backend should query using the same IST offset:

    Replace lines 165-167:
    ```typescript
    // BEFORE (server-local tz, broken in UTC container):
    const startOfMonth = new Date(year, month, 1);
    const endOfMonth = new Date(year, month, numberOfDays + 1);

    // AFTER (IST-explicit boundaries):
    // IST = UTC+5:30. Create boundaries at IST midnight = prev-day 18:30 UTC.
    // month param is 0-indexed (JS Date convention).
    const startOfMonth = new Date(Date.UTC(year, month, 1, -5, -30, 0, 0)); // IST midnight = 18:30 UTC prev day
    const endOfMonth = new Date(Date.UTC(year, month, numberOfDays + 1, -5, -30, 0, 0));
    ```

    The `$gte` and `$lt` operators in the aggregation pipeline will now correctly capture all events within the IST month regardless of the server's timezone.

    Also investigate: the controller calls `getCalendarEventByMonth` with `year` and `month` from route params. Verify these are the same year/month values the frontend sends (check `calendar.api.ts` and `use-calendar.ts` in the frontend for the GET request URL construction).
