# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **Seed runs in-container, not on host** — `pnpm seed` must run as `docker exec saher-backend-1 sh -c 'cd /app && pnpm seed'`. The host invocation resolves the wrong MONGO_URI outside the compose network (`ENOTFOUND mongo`) and writes to a DB nothing reads.
- [ ] CONSTRAINT: **Frontend/backend permission matrices are verbatim mirrors (D-13)** — any change to `saher-backend/src/permission/role-permission.ts` MUST be mirrored into `saher-frontend/lib/permissions.ts`, and the entry-count test in `tests/permissions.test.ts` updated to match.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Seeding the wrong DB | Ran `pnpm seed` on host → connected to a mongod the app never reads; app DB stayed empty | blocking | Always seed through the backend container (bind-mounted `/app/src`) |
| Editing one side of the mirrored permission matrix | D-13 mirror divergence; frontend `can()` gating drifted from backend enforcement | blocking | Update backend role-permission.ts + frontend lib/permissions.ts + permissions.test.ts counts in one change |
| Trusting raw grep for matrix diffs | Grep extraction broke on hyphenated resources (`attendance-correction`, `leaveType`) | advisory | Use a proper JSON diff script (see below) when auditing the matrix |
